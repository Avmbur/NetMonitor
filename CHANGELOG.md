# Журнал изменений NetMonitor

Пользовательские изменения по выпускам.

## 1.0.5 — 2026-10-05

- Карточка тревоги показывает связанный бан: когда поставлен, до какого времени, на каких серверах и что с ним сейчас — действует, истёк или снят. Состояние самой тревоги остаётся отдельным.
- «Открыть бан» есть и у просмотренной тревоги. Открывается тот бан, который поставила эта тревога, в том числе уже истёкший или снятый.
- В плитке «Баны» по умолчанию только живые. Рядом можно открыть истёкшие и снятые, найти адрес и выбрать срок: сутки, 7 или 30 суток.
- Журнал автобана пишет охват и срок. Когда срок кончается, один раз появляется строка «бан истёк».

## 1.0.4 — 2026-10-01

- Плитки «Правила» и «Группы» сортируются щелчком по заголовку столбца: сначала по возрастанию, затем по убыванию, третий щелчок возвращает прежний порядок. Пока группы отсортированы, строки не перетаскиваются.
- Карантин не закрывает открытые вопросы обучения. Вопрос закрывают бан, правило, группа и режим «блок». После снятия карантина неотвеченные вопросы остаются.
- Повтор записи трафика за одну минуту больше не оставляет ошибку в журнале агента.

## 1.0.3 — 2026-09-30

- Правило по DNS-имени учитывает все адреса имени. Пока имя не разрешилось, правило никуда не открыто. Второе правило с тем же именем не создаётся.
- Служебное обновление пускает агент, монитор и установщик обновления только на адреса GitHub, вписанные в фильтр перед соединением. Адрес живёт сутки.
- Список группы по https-ссылке скачивается так же: адрес ссылки вписывается в фильтр до соединения.

## 1.0.2 — 2026-09-30

- Соединения контейнеров Docker показываются с именем контейнера. Наружу и на вход извне для них действуют те же правила, что у хоста.
- Обмен контейнера с хостом и с другими контейнерами не спрашивается. В карантине контейнер к хосту ограничен DNS и ответом на соединение, которое открыл хост.
- Ответ на своё исходящее соединение больше не становится входящим вопросом.

## 1.0.1 — 2026-09-28

- Агента можно забыть на мониторе: строка и сертификат пропадают, программа на сервере остаётся, историю можно продолжить.
- «Удалить с сервера» снимает программу, каталог и таблицу фильтрации. Строка исчезает только после подтверждения машины. Если агент молчит, в окне команда для ручного запуска.
- Правило с портом и протоколом «любой» закрывает на этом порту tcp и udp. Для ICMP порт по-прежнему не задаётся.
- Новая группа, созданная из окна правила, сразу выбрана в этом окне.
- Под полем локальных сетей снова показан пример префиксов.
- В настройках кнопка «Проверить обновление». Монитор и агенты ставятся отдельно из релиза на GitHub.
- Служебное правило выпуска открывает исходящий HTTPS только службам NetMonitor: агенту, монитору и установщику обновления.
- Если новая сборка агента не запустилась, возвращается прежняя программа.

## 1.0 — 2026-09-27

- Первый публичный выпуск.
- Монитор `nmserver` и агент `nmagent` для серверов Ubuntu, amd64 и arm64.
- Сетевая активность парка в одном окне: процессы, адреса, порты, DNS-имена, правила, состояние соединений и трафик.
- Обучение на неизвестных контактах, правила, группы адресов, ручные блокировки и автобаны за сканирование портов и перебор SSH.
- Тревоги, история, аудит действий администратора и 19 отчётов с выгрузкой в CSV.
- Связь агента с монитором по HTTPS с взаимной проверкой сертификатов; при обрыве агент копит события в локальной очереди.
- Одна база SQLite с пределом размера: новые данные вытесняют самую старую историю. Один сменяемый снимок базы.
- Окно «by AVMBUR» с версией и датой выпуска.
